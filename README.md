# 🐺 狼人杀自动法官（预女猎白 12 人 / 预女猎 9 人 / 狼王守卫 12 人 PWA）

让玩家只用自己的手机，就能在线下聚会完成一整局狼人杀 —— **不需要真人法官，也不需要实体身份牌**。创建房间时可选择 12 人「预女猎白」、9 人「预女猎」或 12 人「狼王守卫」。

- 系统自动发牌、主持夜晚流程、结算死亡、主持警长竞选与放逐投票、处理猎人开枪 / 白痴翻牌 / 警徽移交，并按屠边规则判定胜负。
- 所有规则只在服务端结算；玩家手机只能拿到自己有权知道的信息。
- 可「添加到主屏幕」作为 PWA 使用，深色、竖屏、大按钮。
- 角色插画与图标由 Codex 绘制（`public/roles/*.svg`）。

**9 人预女猎**

| 好人 · 神职 | 预言家、女巫、猎人 | 各 1 |
| 好人 · 平民 | 村民 | 3 |

**12 人狼王守卫**

| 阵营 | 角色 | 数量 |
| --- | --- | --- |
| 狼人 | 狼王 | 1 |
| 狼人 | 普通狼人 | 3 |
| 好人 · 神职 | 预言家、女巫、猎人、守卫 | 各 1 |
| 好人 · 平民 | 村民 | 4 |

板子之间的区别：**9 人局女巫仅首晚可以自救**（第二晚起不能），两个 12 人局女巫全程不可自救；9 人局没有白痴。其余流程（警长竞选、1.5 票归票、猎人开枪、放逐遗言等）完全相同。

狼王守卫局的特殊规则：

- **夜间顺序**：守卫 → 狼人 → 女巫 → 预言家 → 猎人状态确认（守卫出局后该步骤用随机等待伪装）。
- **守卫**：每晚守护一名存活玩家（可以守自己，也可以空守），被守护者当晚不会被狼刀；不能连续两晚守同一人；守护挡不住毒药。**同守同救**：守卫守护与女巫解药救的是同一人时效果抵消，该玩家仍然死亡（解药照常消耗）。
- **狼王**：夜间与普通狼人一起刀人，预言家查验为「狼人」。被放逐、被狼刀（自刀）或被猎人带走时，翻牌并可开枪带走一名存活玩家（被狼王带走的猎人同样可以开枪）；**被女巫毒杀不能开枪**。普通狼人能看到哪位队友是狼王。
- 胜负：狼王与 3 名普通狼人全部出局 → 好人胜；4 名神职（预言家、女巫、猎人、守卫）全部出局或 4 名村民全部出局 → 狼人胜。
- 本应用没有「自爆」功能，因此不涉及「狼王自爆不能开枪」的情况。

胜负（屠边）：神职全部出局（屠神）或村民全部出局（屠民）→ 狼人胜；狼人全部出局 → 好人胜。

## 技术架构

```
手机浏览器 (React + Vite PWA)
   │  POST /api/{create|join|state|action}   每 1.5 秒轮询自己的视图
   ▼
Netlify Function  netlify/functions/api.ts
   │  server/api.ts      身份令牌校验 + 读-改-条件写（乐观并发）
   │  shared/engine.ts   规则引擎（唯一可信结算）
   │  shared/view.ts     按玩家裁剪可见信息
   ▼
存储  Netlify Blobs（默认，零配置，etag 条件写入）
      或 Supabase Postgres（可选，rooms 表开启 RLS、无任何策略）
```

| 目录 | 说明 |
| --- | --- |
| `shared/types.ts` | 状态与视图类型 |
| `shared/engine.ts` | 全部游戏规则：发牌、夜晚、结算、竞选、发言、投票、猎人、白痴、警徽、胜负 |
| `shared/view.ts` | 信息隔离：为每位玩家生成只含其可见信息的视图 |
| `server/api.ts` | API 处理（Netlify 与本地开发共用） |
| `server/store.ts` | 存储：内存 / Netlify Blobs / Supabase，全部带版本号比较写入 |
| `src/` | 前端页面（首页、等待室、身份、夜晚、天亮、竞选、发言、投票、猎人、白痴、警徽、结果） |
| `tests/` | 自动化测试 |
| `scripts/bots.mjs` | 机器人玩家（测试用，只通过公开 API 行动） |
| `supabase/migrations/001_rooms.sql` | 可选的 Supabase 表结构 |

### 信息安全与防作弊

- 加入房间时服务端生成随机令牌（24 字节），仅保存其 SHA-256 哈希；所有操作必须携带令牌，服务端据此确定「你是谁」。
- 完整身份表只存在服务端存储中，**从不**整体下发。`buildView()` 只返回：公开信息 + 你自己的身份 + 规则允许你知道的信息（狼队友、预言家查验结果、女巫当晚是否可见刀口与药剂数量）。
- 夜间的子步骤（狼人/预言家/女巫）不对外公开；已死亡的预言家、女巫，其夜间步骤会用随机等待时间伪装，避免通过夜晚时长推断身份。
- 投票在全部提交前只公开「谁已投」，不公开投给谁。
- 游戏结束后才公开全部身份、夜间行动记录与查验记录。
- 房主只是「可以点开始的人」，没有任何额外权限；房主离线不影响游戏（流程由服务端推进，任何在线玩家的请求都会驱动计时结算）。
- 若使用 Supabase：`rooms` 表开启 RLS 且不建策略，anon key 无法读取；只有服务端 service role 访问。
- 并发：每次写入都基于版本号（Blobs etag / Postgres version 列）做比较写入，冲突则重读重放。因此重复点击、同时提交、网络重试都不会重复消耗药剂、重复死亡或重复结算（见 `tests/api.test.ts`）。
- 洗牌与平票随机使用服务端加密安全随机数。

## 规则细节与默认约定

需求未完全定义之处，本项目采用以下清晰、一致、可测试的默认规则：

**流程**
1. 每晚严格按顺序进行，**上一步的玩家全部完成后才轮到下一步**：
   1. **狼人行动**：狼人互相看到身份，共同选择击杀目标（全部存活狼人锁定后结束）。
   2. **女巫行动**：系统告知当晚被刀的玩家（解药未用时），女巫选择救人、毒人或空过。
   3. **预言家行动**：查验一名玩家，系统告知好人或狼人。
   4. **猎人状态确认**：系统告知猎人当晚是否具备开枪资格（被女巫毒杀则不具备），猎人点「我知道了」确认；猎人夜间不主动击杀任何玩家。
   5. 服务端统一结算 → 天亮公布死讯 → 判定胜负。

   某个角色已出局（或本板子没有该角色）时，系统用随机等待时间代替该步骤，避免通过夜晚节奏推断身份。
2. 第 1 天：**先进行警长竞选，竞选结束后才公布首夜信息** → 猎人开枪 / 警徽移交 → 白天发言 → 归票 → 放逐投票。竞选期间首夜死讯完全不公开，所有人都显示存活，首夜出局的玩家仍可上警、投票；若当选警长后才公布其出局，则立即移交或撕毁警徽。之后每天天亮直接公布死讯，不再竞选。
3. 天亮页面任意玩家点「继续」进入下一步（遗言在线下进行）。

**狼人**：每位存活狼人选择并锁定目标（可自刀、可刀队友，必须选择）；队友可实时看到彼此的选择；全部锁定后票多者为刀口，平票随机。

**预言家**：每晚必须查验一名存活玩家（可查自己），只得到「好人 / 狼人」。

**女巫**：解药未用时可看到当晚刀口（包括刀口是自己时；12 人局不能自救，9 人局仅首晚可以自救）；用过解药后不再显示刀口。每晚最多一瓶；毒药可毒任何存活玩家（含自己）；可选择不用药。同时被刀和被毒的玩家只死一次，按「毒杀」处理（猎人不能开枪）。

**猎人**：被狼刀或被放逐可开枪（也可选择不开枪），开枪时公开猎人身份；被毒杀不能开枪，系统自动跳过。猎人出局时若已满足胜负条件，游戏立即结束，不再开枪（屠边即时判定）。

**白痴**：被放逐时**系统自动翻牌**，公开白痴身份，无需玩家操作。**默认（按本项目需求）：翻牌后仍出局**（先发表遗言再确认出局）。房主可在等待室切换为「经典规则」：翻牌免于出局，但失去投票权、之后不能再被放逐；若白痴是警长，警徽流失。被狼刀 / 毒杀正常出局，不翻牌。

**放逐遗言**：任何玩家被放逐后进入「放逐遗言」步骤，在线下发表遗言，然后由本人在手机上点击「确认出局」，之后才处理猎人开枪、警徽移交并进入夜晚。

**警长竞选**
- 所有存活玩家选择上警或不上警，全部选择完毕后才公布候选人名单。0 人上警 → 无警长；1 人 → 自动当选。
- 候选人按随机起点依次发言；发言阶段候选人可「退水」。仅剩 1 名候选人时自动当选。
- 投票：除退水者外的所有存活玩家投票（候选人也可投，但不能投自己），一人一票，可弃票。
- 平票（或全部弃票视为所有候选人平票）→ 平票者 PK 发言 → 平票者以外的玩家重投 → 再次平票则本局无警长。

**警长权力**：决定发言顺序（顺时针 = 座位号递增，从警长下一位开始，警长最后发言）；投票前可归票（公开建议目标，不强制他人）。**归票时警长本轮票重 1.5，不归票为 1。** 警长出局时先处理猎人开枪等死亡效果，再选择移交警徽或撕毁。无警长时白天从随机一位存活玩家开始按座位号递增发言。

**放逐投票**：所有有投票权的存活玩家投票，可投自己、可弃票；全部提交后才公布票型。唯一最高票者出局；全部弃票无人出局；平票 → 平票者 PK 发言 → 平票者以外的玩家在平票者中重投 → 再平票无人出局。

**胜负**：每次死亡结算后（夜晚结算、放逐、猎人开枪）立即判定。若同时满足多个条件，统一按「狼人全灭（好人胜）→ 屠神 → 屠民」顺序判定。游戏结束后所有操作被拒绝。

**断线**：30 秒无心跳显示「离线」。系统不会替离线玩家使用技能或投票；只有发言阶段，若当前发言者离线，其他玩家可跳过其发言。原玩家用同一设备重新打开链接即可恢复座位与进度。

**发言倒计时**：默认 90 秒（房主可设 60 / 90 / 120 / 180 秒），**警长发言比其他玩家多 30 秒**。倒计时只作提示，时间到不会自动淘汰。

**轮到你提醒**：白天轮到自己发言、投票、上警报名、遗言、猎人开枪、警徽移交时，页面顶部显示「轮到你操作了」并震动提示（支持的手机）。**夜间行动刻意不震动**，避免线下房间里旁人听出谁是狼人、预言家或女巫。游戏进行中会请求屏幕常亮（Screen Wake Lock），减少手机休眠导致的掉线。

**私人信息**：白天也会显示只有自己能看到的信息：狼队友、预言家历次查验结果、女巫剩余药剂、被毒杀的猎人提示。

**再来一局**：游戏结束后，房主可以在同一房间点击「再来一局」，所有玩家回到等待室并保留座位，重新准备后即可开始新一局，无需重新扫码。

## 本地开发

需要 Node.js 20+。

```bash
npm install
```

```bash
npm run dev
```

打开 http://localhost:5180 。本地开发时 API 由 Vite 挂载，使用内存存储（重启后清空）。同一局域网的手机可通过 `http://<电脑IP>:5180` 访问。

在同一浏览器模拟多台设备：在网址后加 `?p=任意名字`（例如 `/r/ABC123?p=2`），每个 `p` 值是独立的身份。

用机器人凑满 12 人：先在浏览器创建房间，然后执行（房间代码替换为实际值）：

```bash
node scripts/bots.mjs ABC123
```

不写数量时会自动填满剩余座位（12 人局 11 个、9 人局 8 个）。机器人会自动准备，并在游戏中按各自视图随机进行合法操作，直到游戏结束。

## 部署到 Netlify

**线上地址：https://lrsv2.netlify.app** （Netlify 项目 `lrsv2` 已连接本仓库，推送到 `main` 分支会自动部署）

1. 在 Netlify 选择「Add new site → Import an existing project」，连接 GitHub 仓库 `6VSOFT/LRSV2`。
2. 构建设置会从 `netlify.toml` 自动读取：Build command `npm run build`，Publish directory `dist`，函数目录 `netlify/functions`。
3. 部署即可。默认使用 **Netlify Blobs** 存储房间数据，无需任何环境变量或数据库。

也可以用 CLI：

```bash
npx netlify-cli deploy --build --prod
```

### 可选：改用 Supabase

1. 在 Supabase SQL 编辑器执行 `supabase/migrations/001_rooms.sql`。
2. 在 Netlify 站点的环境变量中设置 `SUPABASE_URL` 与 `SUPABASE_SERVICE_ROLE_KEY`（只在服务端使用，不会下发前端）。
3. 重新部署。设置后服务端自动改用 Supabase。

## 实际测试步骤（12 台手机）

1. 部署后，一位玩家用手机打开网站，输入昵称，点「创建房间」。
2. 其余 11 位玩家扫描等待室的二维码（或输入房间代码）并输入昵称加入；确认第 13 人加入会被拒绝。
3. 每位玩家点「准备」，房主点「开始游戏」并确认。
4. 每位玩家点卡牌背面查看自己的身份（看完再点一次隐藏）。狼人应看到 3 名狼队友，其他人看不到任何他人身份。
5. 夜晚按顺序：狼人选择并锁定刀口 → 女巫用药 → 预言家查验 → 猎人确认开枪状态。确认上一步未完成时下一步角色看不到行动界面。其他玩家只看到「天黑请闭眼」。
6. 第 1 天天亮后先竞选警长：全员选择是否上警 → 候选人依次发言（当前发言者点「发言完毕」，可退水）→ 投票 → 产生警长。此时首夜死讯尚未公布。
7. 竞选结束后公布首夜信息：确认死讯正确，任意玩家点「继续」。若猎人被刀，猎人手机出现开枪界面；若新警长首夜已出局，移交或撕毁警徽。
8. 警长选择发言顺序 → 全员依次发言 → 警长归票或不归票 → 放逐投票 → 公布票型与出局者 → 被放逐者发表遗言并确认出局（白痴自动翻牌、猎人可开枪、警长可移交警徽）。
9. 循环夜晚 / 白天，直到系统宣布胜负。结束页面公开全部身份、查验记录、投票记录与完整日志。
10. 过程中可刷新页面、关闭再打开、切换网络，确认能恢复到原座位和当前阶段；重复点击按钮不会重复结算。

**添加到主屏幕**：iPhone 用 Safari 打开 →「分享」→「添加到主屏幕」；Android 用 Chrome 打开 → 菜单 →「添加到主屏幕 / 安装应用」。
